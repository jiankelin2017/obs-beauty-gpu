## 二、根因是**两层**，缺一层都修不好

### 第一层：`bounds_` 被清空 → 祛斑不进链

`buildMaskInto()` 里包围盒只在**落笔时**更新（`paintSkin`/`paintW` 里改 `bx0/bx1`）。
geomOnly 帧（S4a 显式降频、S4b 缩略图检测）一个像素都不落笔，`bx1` 恒为 -1，
于是 `if (bx1 < 0) boundsOut = RoiRect();` 把它清空 —— 但这不是「掩码全零」，
而是「本帧没画」。

下游 `3942`（GPU 段 `geoOut->spotOn`）与 `3953`（CPU 段 `applySpotFix`）用的是
同一个条件 `!bounds_.empty()`，两条路径一起失效。默认配置 `detect_small=1`
几乎恒走缩略图，所以祛斑自 2.6.0 起基本没生效。

**修法**（`beauty_core.cpp`，`bx1 < 0` 分支）：区分两种情形
- 非 geomOnly → 仍然清空（真的全零掩码）
- geomOnly → **沿用**上一份真实包围盒；若从没建过（缩略图路径下永远没有落笔帧），
  用**本帧脸框** × `kFaceBoxGrow` + padding 兜底。没有这条兜底，修了也白修。

### 第二层：掩码全零 + 逐像素门控 → 算子空转

`applySpotFix()` 主循环第一句是 `const float mw = mrow[...]/255; if (mw <= 0) continue;`。
geomOnly 帧的 `mask_` 是残留或全零，于是「spot=1 已进链、算子逐像素全跳过」，
画面一点变化都没有。

**这一层最初被误判为「函数没被调用」** —— 因为临时诊断的 `fopen` 用了含中文的路径
（`D:/插件/OBS美颜GPU版/05_验证/…`），ANSI 编码下变乱码、静默失败。改成
`%TEMP%` 这样的纯 ASCII 路径后，数据立刻显示：

```
enter dst=1 geo=0 delspot=100.0 faces=1 maskSize=921600 wh=921600 boundsEmpty=0 geomOnly=0
spot=1.00 dst=1 bounds=(538,218)-(852,634) empty=0 geomOnly=0
k=0.25 r=2 thr=[1.4,30.0] roi=314x416 mask=cpu maskNz=0 hit=0 devMax=0.00
```

`maskNz=0` 就是答案：掩码指针有效、内容全零。

**修法**（两处）
1. `beauty_core.cpp`：`maskGeomOnlyFrame_` 为真时不传掩码（`nullptr`）。
2. `beauty_region.cpp`：`applySpotFix` 接受 `mask == nullptr` = 不做掩码门控，
   用 ROI + `dev` 阈值（`[thrLo,thrHi]`）排除细纹理与真边缘。
3. **数据驱动兜底**：不能只信标志 —— 那个标志来自异步检测的上一帧，会错配。
   所以在 `applySpotFix` 里抽样（步长 4）统计 ROI 内掩码非零数，全零就等价于
   `nullptr`。这一步才是真正止血的。

## 四、工具与坑

1. **`fopen` 不能用于中文路径**（ANSI + UTF-8 源码）。三次编译都看不到诊断文件，
   差点误判「函数从未被调用」。诊断输出一律写 `%TEMP%` 下的纯 ASCII 名字。
2. **`static` 计数器在长跑里只出前 N 条**，要定位「每帧都在跑但都没效果」这种问题，
   首次命中就够 —— 但前提是文件真的能写出来。
3. **`BEAUTY_SPOT_DEBUG=1` 现在会写 `%TEMP%/beauty_spot_inner.txt`**（
   `k / r / thr / roi / mask / maskNz / hit / devMax`），比原来写 stderr 有用得多
   （OBS 无控制台）。
4. **测试集合**：`beauty_spot`（720p）/ `beauty_spot4k`，由
   `make_static_collection.py` 生成后把 image 源换成带斑点图。斑点图的生成方法
   见本记录第一节，可复现。
