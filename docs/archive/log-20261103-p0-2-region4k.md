# P0-2 五官 4K 长跑记录（2026-11-03，第 1 次）

## 一、目的与命令

**原目的**：`GPU_REGION`（五官段 GPU 化）默认关，要判断"零 device-lost 就翻默认，否则永久 opt-in"。

**命令**：`py -3 05_验证/soak_s2.py soak --minutes 30 --with-region --region-params`
**素材**：`beauty_soak4k` / 3840×2160 / `face_4k_single.png`（四分之三侧脸）
**被测 DLL**：`BA5363F30075FE1B735C2E0C37733952`（`v2.7.1, engine=gpu/2.0.0`）
**负载**：`LOAD` + `LOAD_REGION`（`eye_bright` 0.5 / `remove_pouch` 0.5 / `remove_nasolabial` 0.5 / `delspot` 0.4）

## 二、稳定性结论：PASS

| 项 | 结果 |
|---|---|
| 时长 / 窗口 / 帧数 | 30:04 / **178 窗 ≈ 32040 帧** |
| OBS 存活到结束 | 是 |
| D3D11 / 驱动异常 | **无**（`BAD_PATTERNS` 零命中） |
| 插件 error 行 | **0** |
| 帧环命中 | `prep=0.00` → 命中 |
| 画面校验（每 10 min） | 三次均 `(3840,2160) mean=117.42 ok` |
| **判定** | **PASS**（T10 崩溃链未复现） |

## 三、性能结论：不可用（往返 57.64 ms / 17.7 fps）

末窗：`下载 7.73 + 引擎 44.88 + 上传 5.03 = 57.64 ms/帧`，帧率 17.7 fps。
段分项：`掩码 2.58 + 磨皮 8.57 + 五官 6.32 + 美形 27.40 = 44.88 ms`，`S/T/R/D/W=180/180/0/0/0`，`claimdrop=180`，`tsm=0`。

### 因果已定位到"下发五官参数"这一刻

| 窗口 | 五官参数 | `W` 认领 | 五官 ms | 美形 ms | 往返 ms | `tsm` |
|---|---|---|---|---|---|---|
| 第 1 窗 | **尚未下发** | **179** | 0.00 | 0.00 | **2.99** | **178** |
| 第 2 窗 | 刚下发 | 51 | 4.31 | 19.36 | 32.25 | 52 |
| 第 3 窗起 | 已下发 | **0** | 5.60 | 27.16 | 44.20 | **0** |

同一份素材、同一台机器、同一份 DLL：**不下发五官参数时 4K 往返 2.99 ms，下发后 57 ms**。因此这不是素材问题、不是稳定性问题，而是**功能耦合**：

1. 五官参数一生效，美形段（`W`）从"GPU 认领 179/179"掉到 **0**，整段回落 CPU，代价 27 ms；
2. 连带缩略图路径（`tsm`）从 178 → 52 → **0**，下载从 0.81 ms 涨到 7.73 ms（整帧回读 33 MB）；
3. 两项叠加就是 57 ms。`claimdrop=180`（源码注释：认领位不满，本帧走了 CPU/回退）与之一致。

**机制层面的归因我只做到这一步。**"为什么五官参数会让 `W` 与 `tsm` 同时失效"——是认领位被 region 段抢占、还是 `thumb_prev_ok` 被拉低后不再恢复——**尚未定位，属待办**。本次记录只陈述可观测事实。

## 四、对决策的影响

原验收口径是"零 device-lost → 翻默认"。稳定性确实 PASS，但性能条件另立了一条硬否决：**4K 下 17.7 fps 无法用于直播**。因此判定：

- **`BEAUTY_GPU_REGION` 不翻默认，维持 opt-in**；
- 需在文档中写明：开启五官后 4K 会掉到约 57 ms/帧，**不适合 4K 直播**；
- 该耦合本身是一个**独立缺陷**（A/B：`BEAUTY_GPU_REGION=0` 时 4K 回到 2.99 ms），应单独立项，而不是当作"五官功能就这样"。

## 五、与"侧脸素材"的关系

素材确为四分之三侧脸，但本记录证明**侧脸不是本次退化的原因**：第 1 窗用的就是这张侧脸图，往返 2.99 ms、`tsm=178`。因此侧脸只影响"覆盖率/五官几何的代表性"，不解释这次 57 ms。

## 六、第 2 次 30 分钟（同日补跑）

| 项 | 第 1 次 | 第 2 次 |
|---|---|---|
| 时长 / 窗口 / 帧数 | 30:04 / 178 窗 ≈32040 帧 | 30:04 / **184 窗 ≈33120 帧** |
| 末窗往返 | 57.64 ms | **54.02 ms**（下载 6.88 + 引擎 42.24 + 上传 4.91） |
| 帧率 | 17.7 fps | 18.4 fps |
| 末窗分项 | 磨皮 8.57 / 五官 6.32 / 美形 27.40 | 磨皮 8.21 / 五官 5.04 / 美形 26.41 |
| `S/T/R/D/W` | 180/180/0/0/0 | 180/180/0/0/0 |
| `tsm` | 178 → 52 → 0（176 窗为 0） | **0（184/184 窗，从头到尾）** |
| D3D11 异常 / error | 无 / 0 | 无 / 0 |
| 判定 | PASS | **PASS** |

**两次结论一致**：稳定性 60 分钟无异常（合计 592 窗 / 65160 帧），性能全程 54–58 ms。

第 2 次从第 1 个测量窗起 `tsm=0`、往返 54.65 ms —— 因为这一轮五官参数在首个 perf 窗口之前就已下发，**没有出现第 1 次那种"首窗 2.99 ms"的空档**。这反过来印证：第 1 次那个 2.99 ms 窗口只是"参数尚未下发"，不是路径能自愈的证据。

## 七、最终判定

- **稳定性**：30 min ×2 全 PASS，T10 崩溃链未复现 → 稳定性这一项**不是**阻塞原因。
- **性能**：4K + 五官参数 = **54–58 ms/帧、17.7–18.4 fps**，不可用于直播 → **`BEAUTY_GPU_REGION` 维持 opt-in，不翻默认**。
- **独立缺陷**：五官参数一生效即打掉美形段的 GPU 认领与缩略图路径（`W` 179→0、`tsm` 178→0）。关掉 region 立刻回到 2.99 ms，说明这是耦合缺陷而非硬件极限。**建议单独立项**，优先级高于 S6。
