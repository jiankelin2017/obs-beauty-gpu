## 二、4K 祛斑像素判据（补 §9.22.4 的空白）

新增工具 `05_验证/verify_spot_pixels.py`：同一帧内容取两张源截图（滤镜开 / 关），逐像素比。
只开祛斑一项，其余面板参数全 0 —— 磨皮的存在会把几灰阶的斑点差盖掉。

集合 `beauty_spot4k`（素材 `05_验证/out/face_spot_4k.png`，12 个半径 3px、深度 26 灰阶高斯暗斑）。

| 档位 | maxdiff | 差异像素 | 占比 | 变化 bbox | ROI（内层诊断） | 判定 |
|---|---|---|---|---|---|---|
| **0** | **0** | **0** | 0.0000% | — | 无诊断文件（算子在面板 0 时直接返回） | PASS（阴性对照） |
| 40 | 3 | 73 229 | 0.8829% | (1613,658)-(2546,1918) | 934×1261 | PASS |
| 100 | 7 | 220 005 | 2.6525% | (1613,658)-(2546,1918) | 934×1261 | PASS |

- **0 档必须是 0 像素** —— 已满足，说明这个判据量的确实是祛斑，不是噪声或截图差异。
- 40 → 100 单调（maxdiff 3→7，像素 73k→220k），且 `hit=329910` 两档相同：候选集合与档位无关，
  变的只是混合强度 —— 与算法结构一致。
- 变化 bbox 落在 ROI 内且不贴边，说明作用域是脸框而不是整帧。

同档 720p 对照（`beauty_spot` / 1280×720，档位 100）：maxdiff 7、**48 926 像素**（5.31%），
bbox (534,217)-(851,641)。4K 像素是 720p 的 9 倍，改动像素只有 4.5 倍 —— **亚线性**，
因为斑点半径固定 3px，在高分辨率下占的脸面积反而更小。方向正确。

## 三、两个新发现（都比原结论更值得记）

### 3.1 `--collection` 匹配的是集合 JSON 里的 `name`，不是文件名

4K 祛斑三轮「被上一个 OBS 会话接管」的真因找到了，**不是会话残留**：

```
beauty_spot.json   内部 name = beauty_soak720   ← 从 soak 集合复制出来的，name 没改
beauty_spot4k.json 内部 name = beauty_soak4k
```

`--collection beauty_spot` 匹配不上，OBS **静默回退到「上次用的集合」**。症状极具误导性：
画布日志明明写着 `base resolution: 1280x720`，插件自己的日志却是 `target=still 3840x2160`
—— 插件没骗人，它处理的就是那张 4K 图。

本轮在 `verify_spot_pixels.py` 里把内部 `name` 一起改成文件名（跑完原样写回），一次就通。
判据：输出里出现 `素材/截图尺寸 : 1280x720（插件首帧 render=1280x720）`。
工具末尾还加了尺寸自检，`render` 与截图不一致会打 WARN。

### 3.2 祛斑在 geomOnly 帧不做掩码门控 → 强度随帧类型跳

内层诊断（`%TEMP%/beauty_spot_inner.txt`）显示本轮所有采样帧都是 `mask=null`（geomOnly 帧），
于是 `hit=63652 / roi=318×425` —— **ROI 里 47% 的像素都改了**。而 `P0-8_fix_20261103.md`
记录的那轮是 7037 像素（0.76%），差 7 倍，原因只能是那一轮采样到了 `mask=cpu`（有掩码门控）的帧。

按 P0-8 的设计这是**有意为之**（掩码全零时不做门控，否则算子空转），但它带来一个副作用：
同一段静止画面里，非 geomOnly 帧按皮肤掩码门控、geomOnly 帧不门控，**祛斑强度会在帧间跳**。
本轮在 720p 做了 12 次时序采样（间隔 80 ms），`diffpx` 恒为 48 926 —— 没抓到跳变，
但采样全部落在 geomOnly 帧上，**这只能证明「这一小段时间里帧类型没变」，不能证明不跳**。

处置建议：记为观察项（P0-9），不要在本轮改代码 —— 改门控规则会再动默认画面，
需要先有「跳变幅度」的量化判据（例如连续 60 帧的 `diffpx` 时间序列，取 max/min）。

> **后续（22:08 补充）**：上面这个判据已经跑完，见 `P0-9_geomonly_gate_20261103.md`。
> 60 帧极值比 **1.00**，判为不跳、不改代码；同时本节开头「差 7 倍」的口径被纠正为 **1.58 倍**
> （原文混用了 ÷ROI 与 ÷全图两个分母）。

## 四、工具与坑

1. 新增 `05_验证/verify_spot_pixels.py`：
   ```bat
   py -3 05_验证\verify_spot_pixels.py --collection beauty_spot4k --canvas 3840x2160 --level 100
   py -3 05_验证\verify_spot_pixels.py --collection beauty_spot --canvas 1280x720 --level 0   :: 阴性对照
   ```
   `--probe N` 额外做 N 次时序采样；`--level` 是**面板刻度 0..100**，不是 0..1。
2. **`--collection` 打偏是静默的**，唯一可靠的自检是「插件日志的 `target=` 尺寸 == 素材尺寸」。
3. 诊断输出一律 `%TEMP%` + ASCII 名（`fopen` 中文路径静默失败的坑，§9.22.5 已记）。
4. OBS 只留最近 10 份日志，本轮 4 份 S0 日志已确认未轮转；长跑前先复制到 `out/logs/`。
