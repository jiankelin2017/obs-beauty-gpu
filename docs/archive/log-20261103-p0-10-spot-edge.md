# P0-10 定性：GPU 五官段祛斑的 178 像素差异来自 ROI 边界窗口实现

- 日期：2026-11-03 22:30
- 插件版本：2.9.0（本轮只诊断，未改代码）
- 起因：`PROGRESS §9.22.4` 记「`--only spot` 对拍 maxdiff=4 / 178 像素，属 opt-in 路径的覆盖缺口」
- 结论：**不是不可消除的浮点噪声，是 ROI 边界处两套窗口实现的语义差**。CPU 用截断窗口，
  GPU 用 clamp 重复窗口 + 去重分母。**可修**。

---

## 一、复现

```
py -3 05_验证/verify_region_samemask.py --collection beauty_soak720 \
      --canvas 1280x720 --only spot --samples 1
```

```
样本 1/1：maxdiff=4  差异 178(0.0193%) bbox=(602,472)-(784,633)
         平均偏差=2.219101 掩码来源=GPU 覆盖率=12.8% els=0+0+0 spot=1 → 失败
```

`els=0+0+0` 证明只跑了祛斑这一族，参数确实生效（不是「另外三项也在跑」的假象）。
内层诊断：`k=0.10 r=2 thr=[1.4,30.0] roi=314x416 mask=cpu maskNz=103768 hit=49662`。

## 二、判别实验：差异随 k 的变化

用 `BEAUTY_REG_SPOT`（`beauty_core.cpp:1367`，直接改 `regSpotK`）扫 k，
命中判据 `ad∈[thrLo,thrHi]` 与 k 无关，只有 pull 的幅度随 k 变 —— 于是能分清
「命中集合不同」与「改动量不同」：

| `BEAUTY_REG_SPOT` | 实际 k | maxdiff | 差异像素 | bbox |
|---|---|---|---|---|
| 0.000001 | 4e-7 | **0** | **0** | — |
| 0.125 | 0.05 | 2 | 174 | **(602,632)-(783,633)** ← 只有 2 行 |
| 0.25（默认） | 0.10 | 4 | 178 | (602,472)-(784,633) |
| 2.5 | 1.00 | 37 | 227 | (602,351)-(797,633) |

两条结论：

1. **k→0 时差异归零** ⇒ 不存在坐标错位、掩码采样错位、坐标系系统性偏差。
2. **差异有一个不随 k 变化的「底座」**（174 像素），并且它**贴在 y=632~633 两行上**。
   随 k 增大的那部分（174→227）才是浮点累加顺序导致的取整跨界，属正常数值残差。

一条 2 像素高的水平带，配上 `roi=314x416` 这个尺寸 —— 指向 ROI 的底边。

## 三、离线复算：用落盘原图重现那 178 个像素

`BEAUTY_M1_DUMP_DIR` 落盘 `region_src_rgba` 与 `region_mask`（对拍失败时才写），
用 `05_验证/analyze_spot_edge.py` 按两种窗口实现各算一遍：

- **CPU**（`beauty_region.cpp:386-414`）：`yA=max(ly-r,0)`、`yB=min(ly+r,bh-1)`，
  分子只加 `yA..yB`，分母 `(yB-yA+1)` —— 与「实际参与元素数」一致，**范围外不计入**。
- **GPU**（`region.hlsl:319-351`）：采样点 `clamp(px+k, roiMin+0.5, roiMax-0.5)`，
  边缘的采样**重复**同一个像素（分子含重复）；分母 `nx/ny` 用 `floor` 算的
  **去重行/列数**。两件事对不上。

ROI 从 `roi=314x416` 与差异带位置反推为 `(535,218)-(849,634)`：

```
窗口均值：截断 vs clamp 重复（只统计 ROI 内）
  不同的像素   : 102399
  最大均值偏差 : 377.931 灰阶
=== 两种窗口实现的结果差异（k=0.100 r=2 thr=[1.4,30.0]）===
  命中像素     : CPU 49665 / GPU 49776
  maxdiff      : 4
  差异像素     : 177
  bbox         : (602,632)-(784,633)
  非零处平均偏差: 2.23 灰阶
```

与插件内实测逐项对上：

| 项 | 实测 | 离线复算 |
|---|---|---|
| maxdiff | 4 | **4** |
| 差异像素 | 178 | **177** |
| 平均偏差 | 2.219 | **2.23** |
| bbox 上沿 | 472（k=0.10）/ 632（k=0.05） | **632** |
| 命中像素 | 49662 | 49665 |

「最大均值偏差 377 灰阶」看着吓人，但它的位置是 **ROI 右下角 (848,218)，那里 `mask=0`** ——
两边的 `mw <= 0 → continue` 都跳过，不参与输出。`diff > 85 灰阶` 的 660 个像素同理，
全在掩码为零的角落。真正参与输出的差异就是那 177 个。

## 四、根因

```
CPU：窗口截断            分子 = Σ(yA..yB)              分母 = (yB-yA+1)
GPU：窗口 clamp 重复     分子 = Σ(clamp 后 2r+1 次)    分母 = 去重行数
```

在 ROI 中心两者等价（都不触发 clamp）。在距边界 `< r` 的行/列上：

- CPU 例如 y=632（ROI 底边 634、r=2）：取 630..633 共 4 行，除以 4。
- GPU 取 630.5/631.5/632.5/633.5/**633.5**（第 5 次被 clamp 成 633.5）共 5 个采样，
  除以 4 → **多算了一整行**，均值偏大 ⇒ `dev` 偏小 ⇒ `pull` 偏小 ⇒ 与 CPU 差 1~4 灰阶。

这与 `beauty_region.cpp:381-385` 那条注释记的历史 bug 是同一个坑的镜像版本：
那次是「分母用了 win²、分子实际 4 行」，这次是「分子重复了、分母去重了」。

## 五、修复（2.9.1 已实施）

把 `region.hlsl` 的 `PS_SpotSumH` / `PS_SpotMeanV` 从「clamp 重复」改成「窗口外不加」：

```hlsl
int iy = (int)floor(px.y);
int lo = max(iy - sRadius, (int)roiMin.y);
int hi = min(iy + sRadius, (int)roiMax.y - 1.0);
float sum = 0.0;
for (int k = -6; k <= 6; k++) {
    int yy = iy + k;
    if (yy < lo || yy > hi) continue;      // 截断，不是 clamp
    sum += image.SampleLevel(imageTex, float2(px.x, yy + 0.5) / texSize, 0.0).r;
}
// 分母 = (hi - lo + 1)，与上面 skip 的集合完全是同一批
```

横向同理（`nx` 在纵向 pass 里按同一套 `lo/hi` 算）。
**报告与分母现在描述的是同一批像素** —— 这是与 CPU 对齐的全部要求。

## 六、复验

版本 2.9.1，dll MD5 `1AB668A44D0E4CDB2A0C0CB44ABACC36`，570880 B。

| 场景 | 修复前 | 修复后 |
|---|---|---|
| 720p，k=0.05 | 174 像素 / maxdiff 2 | **0 像素 / 0** |
| 720p，k=0.10（默认，3 样本） | 178 像素 / maxdiff 4 | **1 像素 / 1**，三样本逐位相同 |
| 720p，k=1.00 | 227 像素 / maxdiff 37 | **3 像素 / 1** |
| 720p，四族全开（3 样本） | — | **5 像素 / 1**，三样本逐位相同 |
| 4K，k=0.10（2 样本） | 未测（本轮首测） | **1 像素 / 1**，两样本逐位相同 |

判定全部 **PASS**（判据 `maxdiff ≤1`，未放宽）。
k=1.0 那组从 maxdiff 37 掉到 1，说明原来那个 37 也主要是边界 bug 在放大强度。

**效果没有被修掉**：`verify_spot_pixels.py --level 100 --env BEAUTY_GPU_REGION=1`
（GPU 生产路径）仍是 **48 926 像素 / maxdiff 7**，与 CPU 路径的 48 926 同值；
变化 bbox `(534,217)-(851,641)` 与 ROI `(535,218)-(849,634)` 吻合。

## 七、教训

「opt-in 路径的小差异」不等于「可以接受的数值噪声」。这次四个判别实验串起来只花了
约 3 分钟（三次 OBS 会话 + 一次离线复算），代价远低于把它当成"已知差异"写进文档。
判「可接受」之前先做「差异是否随参数变化」这一步 —— 一个不随强度变化的差异底座，
几乎总是结构性的。

第二条：**给 shader 写 pass 时，"分母按实际参与元素算" 这句注释本身不够**，
必须同时确认**分子也只加了那些元素**。CPU 侧的注释（`beauty_region.cpp:381-385`）
记的是「分母写大了」，这次是「分子加多了」—— 同一个坑的两头。
