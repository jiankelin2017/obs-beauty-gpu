# P0-7 定位：差异不在五官算法，在验收工具本身

2026-11-03 晚，2.8.2（诊断版）。结论先说，数据在后。

## 结论

**① 先查出一个比 P0-7 更严重的问题：验证脚本的面板尺度错了 100 倍。**
`05_验证/soak_s2.py` 的 `LOAD_REGION` 写的是 0..1（`eye_bright: 0.5`），而面板刻度是
0..100（`beauty_params.h` 的 `g_params` 注释：「面板刻度统一 0..100，value = panel / 100
× max_val」）。传 0.5 等于把滑块拖到 0.5%，五官效果只剩 1%。已修正为 50/50/50/40。

**② P0-7 的 `maxdiff=8` 不能归因于五官算错。** 同一帧、同一份掩码下，插件自带的
五官整段对拍（GPU 链 vs CPU 基准）给出 **maxdiff=0**。

**③ 截图对拍法在 geomOnly 路径上不成立。** 四路子项单独开、差异量级与 bbox 完全一样；
关掉 geomOnly 差异反而变大（23 / 8.91%）。这说明量到的是「两次独立运行之间的状态差」，
不是「两套算法之间的差」。这一项以前被当成算法判据，是**用错了工具**。

**④ 因此 P0-7 既不能判通过，也不能判失败。** 它是**验收工具缺口**，不是已知缺陷。
`BEAUTY_GPU_REGION` 维持 opt-in 的结论不变——但理由从「像素不达标」改为「无可靠判据」。

---

## 1. 面板尺度：100 倍偏差

`beauty_params.h` 参数表原文：

```
// 每一行是属性页上的一个滑块。key 同时是 OBS settings key……
// 面板刻度统一 0..100，max_val 是面板 100 对应的内部量程
// （value = panel / 100 * max_val）。
{"eye_bright", "亮眼", 0.0, 1.0},   // 0.0 是默认值，1.0 是 max_val
```

引擎侧 `applyFaceRegions()` 一律 `clampi01(s.panel[P_XXX] / 100.0)`。所以：

| 脚本传值 | 引擎收到的 | 实际强度 |
|---|---|---|
| `eye_bright: 0.5`（旧） | 0.005 | **0.5%** |
| `eye_bright: 50`（新） | 0.5 | 50% |

诊断日志直接坐实：修正前 `beauty_region_upload_els` 打印出的椭圆增益 `B.z = 0.060`
（= `regEyeGain 12.0 × 0.005`），修正后应为 6.0。

**这个偏差解释了两件事：**

1. 五官效果只有 1%，累加后大多不足 0.5 灰阶，取整后被完全抹平。所以 GPU 与 CPU
   的差异只能落在「取整阈值」上，表现为「1 LSB 占 99%」——这正是 §9.17.4 记的现象。
2. `LOAD` 里 `thin_face: 0.6 / big_eye: 0.6 / chin: 0.4` 是同一个笔误（应为 60/60/40）。
   **美形段的效果也一直只有 1%**，它的正确性同样从未在真实强度下验证过。本次未动
   `LOAD`（动了会让所有历史基线不可比），列为遗留。

---

## 2. 修正后：四路子项，差异一模一样

`verify_region_geomonly.py` 新增 `--only eye|pouch|naso|spot`，一次只开一路。
720p、`beauty_soak720`、同机同晚：

| 只开 | maxdiff | 差异像素 | 占比 | bbox |
|---|---|---|---|---|
| eye（亮眼） | 8 | 5194 | 0.564% | x[512,873] y[232,710] |
| pouch（去黑眼圈） | 8 | 7197 | 0.781% | x[512,873] y[232,710] |
| naso（去法令纹） | 8 | 9499 | 1.031% | x[512,873] y[232,710] |
| spot（祛斑） | 8 | 3338 | 0.362% | x[512,873] y[232,710] |
| 全开 | 8 | 14346 | 1.557% | 同上 |

**四路的 bbox 完全相同，而且 `maxdiff` 都是 8，≥8 的像素都恰好是 (574,628) 与 (574,629)
这两个位置。** 如果差异来自某一路算子，四个子项不可能给出同一组坐标。

看那两个像素的邻域，形态是一条**一像素宽的竖线**：

```
x=572  573  574  575  576
GPU  178  178  176  184  184     ← x=574 整列低 8 档
CPU  178  178  184  184  184     ← 没有这条线
```

掩码边界上「这一列算不算皮肤」的判定不同，五官段 `acc *= mw` 就把整个 `acc`（约 6~8
灰阶）差了出来。

---

## 3. 同帧对拍：maxdiff=0

插件自带 `beauty_gpu_region_selfcheck()`（`BEAUTY_REGION_CMP=1`）走的是**与生产完全
同一个** `beauty_region_chain()`，然后在**同一帧、同一份 CPU 掩码、同一套几何**上跑一遍
CPU 参考实现，逐像素比：

```
五官整段对拍 1280x720：maxdiff=0 差异像素=0(0.0000%) bbox=(1280,720)-(-1,-1)
平均偏差=0.000000 | faces=1 ellipses=6+2+2 spot=1 判定=通过（≤1 灰阶）
```

`ellipses=6+2+2`、`spot=1`，几何齐全；结果是**逐像素相同**。

---

## 4. 关掉 geomOnly，差异反而变大

```
默认（geomOnly 生效）        maxdiff=8   1.557%
BEAUTY_MASK_GEOM_ONLY=0     maxdiff=23  8.912%
```

如果差异是「GPU 重画掩码的精度问题」，关掉 geomOnly 换成 CPU 掩码应该变好。实测变差
三倍——说明量到的主要不是掩码精度，而是**两路所处的状态不同**。

推断（这部分是推断，未取证）：截图对拍是**两次独立启动 OBS**。geomOnly 帧里
`mask_` 是上一次非 geomOnly 帧的残留（`beauty_core.cpp:2634` 判 geomOnly、`2816`
`if (geomOnly) continue;` 跳过重画，也不清空）。于是 GPU 侧用「本帧几何重画的掩码」、
CPU 侧用「残留掩码」，两者本来就不是同一份东西。静态素材下差异小，边界处差异大。

---

## 5. 自检本身也不可靠

默认配置下 `gonly` 恒为 176~180/180（S4b 用缩略图检测，`mapped=true` 使
`geomOnly=(mapped || g_maskGeomOnly) && …` 恒真），而自检要求 `job.mask` 非空。
三次采集只有一次凑巧碰上非 geomOnly 且有脸的帧。

**所以「自检 maxdiff=0」目前只有 1 个样本。** 它是强证据（同帧同掩码），但样本量不足以
定案——尤其它是在 1% 强度下跑的，效果几乎为零，`maxdiff=0` 的说服力要打折。

---

## 6. 性能：强度修正不影响耗时

4K、`--with-region --region-params`、50% 强度、2 分钟（同一构建）：

| 项 | 1% 强度（§9.17.3） | 50% 强度（本次） |
|---|---|---|
| 往返 | 2.10 ms | 2.03–2.47 ms |
| 引擎 | 1.30 | 1.34 |
| `S/T/R/D/W` | 180/180/180/0/180 | 180/180/180/0/180 |
| `gskip`/`tskip` | 0/0 | 0/0 |

符合预期：GPU pass 的趟数与参数无关，增益只影响像素值。**§9.17 的 54→2.10 ms 结论仍然成立。**

## 7. 处置

- `BEAUTY_GPU_REGION` **维持 opt-in**。理由更正为「缺可靠判据」，不是「像素不达标」。
- **P0-7 改判**：从「五官 GPU/CPU 差异未定位」改为「**geomOnly 路径缺少可用的正确性判据**」。
- 截图对拍（`verify_region_geomonly.py`）保留，但**不得用于 geomOnly 路径的判据**；
  它的 bbox/分布仍可用于观察。新增 `--only` 便于拆子项。
- 修好验证脚本的面板尺度（`soak_s2.LOAD_REGION`），并在文件里写清单位。

## 8. 遗留

1. **建立 geomOnly 帧可用的自检**：读回 `beauty_mask_skin(f)` 作为 CPU 基准的掩码，
   比较「同一份掩码 + 两种算法」。这是唯一能隔离算法的做法，也是 P0-7 定案的前提。
2. **美形三项的尺度笔误**（`thin_face 0.6` 应为 60）。改它会让现有基线失效，
   需重固化；改完还要重跑美形的正确性与性能。
3. **CPU 路径在 geomOnly 帧用残留掩码**（上面第 4 节的推断）。如果成立，未开
   `BEAUTY_GPU_REGION` 的用户在默认配置下的五官段一直用着旧掩码。待取证。
4. 2.8.2 里的诊断日志（`BEAUTY_REGION_DBG=1`）默认关闭、零行为影响，保留备用。
