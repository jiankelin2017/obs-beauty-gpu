## 二、修的是什么

`beauty_region_chain()` 的第一道守卫原来是：

```c
if (!in_tex || !job.mask || rg.faceCount != 1)
    return NULL;
```

`job.mask` 是**CPU 掩码指针**。而 S7 自适应降频之后，静止内容下 8 帧里有 7 帧是 geomOnly：
引擎只交几何、不建 CPU 掩码，`job.mask == nullptr`。于是五官链每帧在第一个 `if` 就返回 NULL，
`REGION` 不认领 → `region_blocks` 为真 → 细节与美形被前缀规则连带挡住 → 整帧交回 CPU，
并因「上一帧未全认领」关掉缩略图路径 → 4K 整帧回读（`下载 7.05 ms`）+ 上传 5.17 ms。

证据（`05_验证/out/logs/p02_region_run2.txt`，2.7.1 那次 30 min）：

```
下载 7.05 + 引擎 42.43 + 上传 5.17 = 54.65 ms/帧
gonly=179  masknull=179  claimdrop=179   S/T/R/D/W=179/179/0/0/0
```

`masknull` 与 `gonly` 逐窗相等 —— 每帧都没有 CPU 掩码。

修法：判据改成「本帧有没有**掩码纹理**」。链实际绑的是 `beauty_mask_skin(f)`，
它返回 `mask_skin_use ?: skin_tex`；geomOnly 帧里 `mask_skin_use` 正是 GPU 按几何重画的那张。

```c
if (!in_tex || (!job.mask && !f->mask_skin_use) || rg.faceCount != 1)
    return NULL;
```

**多脸仍然放弃**（`rg.faceCount != 1` 未动）—— 那是设计边界，不是这次的修复目标。

## 四、像素对拍（这是没通过的那一项）

方法：同一集合、同一组参数、同机，A 跑 `BEAUTY_GPU_REGION=1`、B 跑 `=0`，
两边都等 2.5 s 稳定后抓**程序截图**，逐像素比。脚本 `05_验证/verify_region_geomonly.py`。

| 配置 | maxdiff | 变化像素 | 变化% | mean_abs |
|---|---|---|---|---|
| 4K（3840×2160） | **8** | 37105 | 0.447% | 0.0019 |
| 720p（1280×720） | **8** | 3338 | 0.362% | 0.0014 |
| 4K，**五官参数全零**（对照组） | **0** | 0 | 0.0% | 0.0 |

三件事因此成立：

1. **差异只在五官段。** 五官参数全零时两路逐像素相同 —— 说明 GPU 链的磨皮/色调/美形与 CPU 完全一致，
   掩码也是同一份（否则磨皮会先差出来）。差异全部来自五官这一段。
2. **不是 4K 特有。** 720p 与 4K 的变化率同量级（0.36% / 0.45%），maxdiff 都是 8。
3. **主体是 1 LSB。** 4K 下 37105 个差异像素里 36888 个只差 1；≥2 的 217 个；
   ≥4 的 95 个，且**全部落在 31×36 的一个小块**（x 1727–1758，y 1847–1883）。

**未定位**：那 95 个较大的差异集中在同一小块，形态不像随机浮点噪声，更像某个点状特征
（斑点/纹理边界）被两路判成了不同结果。我试过「只关祛斑再对拍」，但那次覆盖没生效
（关祛斑前后的 GPU 截图逐像素相同，maxdiff=0），所以这个实验作废，不能作为祛斑的结论。

**为什么 R1 记的是 ≤1、≤3 像素**：R1 是 3.1.72 在**全帧掩码**条件下测的，那时还没有 S7 的
每 8 帧降频，`job.mask` 几乎每帧非空；本次是 geomOnly 路径，两条路扫到的帧不同。
这一点是我的推断，没有原始记录可以核对，如实标注。

## 五、处置

- **`BEAUTY_GPU_REGION` 维持 opt-in**，不翻默认。像素未达口径，翻默认就是拿画质换帧率。
- 2.8.1 已装机。默认配置（五官参数为 0，或 `BEAUTY_GPU_REGION` 未设）行为零变化。
- **新增遗留项 P0-7**：五官段 GPU/CPU 在 geomOnly 路径上的 1 LSB 差异 +
  单块集中差异（≤8），定位到具体子项（椭圆 / 法令纹 / 下瓣 / 祛斑）后再决定是否收敛。
- 文档同步：表 A 的 4d 行、表 B 第 9 项、`开关总表` 的 `ASYNC_STAGE`/`GPU_REGION` 说明。
