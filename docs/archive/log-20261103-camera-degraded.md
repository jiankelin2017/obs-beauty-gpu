# 摄像头劣化输入观测（附加项，不进基线）

**日期**：2026-11-03 19:25–19:28
**构建**：2.8.1，集合 `beauty_s1`（源 `视频采集设备` / 滤镜 `OBS美颜`），画布 1280×720
**设备**：`Integrated Camera`（USB\VID_5986&PID_2175，硬件上限 720p）
**日志**：`%APPDATA%\obs-studio\logs\2026-11-03 19-25-38.txt`（29 窗 / ≈5220 帧）

---

## 一、为什么要单列一支

`soak_s2.py` 里的源名/滤镜名是静态集合那一套（`still` / `Beauty`）。拿它驱动摄像头集合时
`SetSourceFilterSettings` **静默打偏**：参数没下发、`self-check` 行显示 `blur=0`、
`ALLZERO_SKIP` 生效、全程 `有脸 0%`、`往返 0.00`，脚本却照常打印「存活」。
19:15 那一轮就是这么废掉的（56 个窗口全 0）。所以这里用 `cam_probe.py`，显式指定
`--source 视频采集设备 --filter OBS美颜`，并**读回参数**做断言。

另外 `BEAUTY_PROFILE=1` 必须显式传：性能行没有它不打印，解析器会得到 0 窗（19:22 那轮踩的就是这个）。

## 二、观测值

| 指标 | 结果 |
|---|---|
| 有脸% | 最小 **1**、最大 100、平均 **72.4**；**14 / 29 窗低于 100%** |
| `dper`（检测周期） | 取值 **{0, 7}** —— 在「每帧」与「每 8 帧」之间来回跳 |
| `dmot`（运动量） | 全部 29 窗都 > 0，取值 6 ~ **235** |
| `gskip` / `tskip` | 非零窗 **0 / 0** |
| 往返 | 1.09 ~ 4.17 ms，中位 **1.57** |
| 异常 / error | 无 / 0 |
| 掩码% | 0.00 ~ 0.09 —— **不可用**，本构建该字段恒近 0（`README` 已有说明） |

## 三、能得出的结论（都很有限，逐条标清）

**1. 人脸检出在真实摄像头上会大幅摆动。** 3 分钟里 `有脸%` 从 1% 到 100%，14 个窗口不是满值。
这与静态图素材（100% 稳定）完全不同。

**2. S7 的运动判据在这个输入上几乎一直认为「有运动」。** `dmot` 每窗都 > 0、最高 235，
`dper` 因此在 0 与 7 之间反复切换。S7 的收益（静止时 CPU 0.476 → 0.101 核）**依赖「判定为静止」**，
而真实摄像头噪声 + 自动曝光的变化就足以让它判成运动。**这是 S7 在真实场景下收益可能打折的第一个实测线索。**

**3. 没有出现整帧跳过。** `gskip=0`、`tskip=0`，说明链路没有因为劣化输入而掉帧。

---

## 四、不能得出的结论（必须说清）

- **不知道镜头前有没有一张稳定的人脸。** `有脸%` 掉到 1% 的窗口，可能是检测失败，也可能是人不在画面里、
  或转头、或光线变了。这一条无法从日志区分，所以**不能把 `有脸%` 当成检测精度**。
- **不知道 `dmot` 高是噪声还是真人动作。** 我坐在键盘前操作，画面里本来就有动作；
  笔记本内置头还有自动增益/自动曝光，逐帧亮度本来就会变。**要分清这两者需要固定光源 + 静止被测对象，
  今晚没做。**
- **掩码覆盖率这一项无效**（字段恒近 0），所以「噪声会不会让掩码乱跳」这个问题**没有回答**。
- 因此：本节全部数字**只能作观察记录**，不构成对检测精度、S7 收益、掩码稳定性的任何判定。

---

## 五、如果要继续，需要什么

1. 固定光源（关掉自动曝光或加台灯）+ 被测者静止坐在镜头前，才能把「噪声」与「真动作」分开；
2. 用 `cpu_probe.py` 在**同一摄像头输入**上量 CPU 核数，才能回答「S7 在真实输入下还剩多少收益」——
   这是比往返更直接的判据；
3. 想要掩码覆盖率，得先修 `性能` 行的「掩码%」字段（当前恒近 0），否则一直测不到。

以上三条都是**新增工作**，未开工。
