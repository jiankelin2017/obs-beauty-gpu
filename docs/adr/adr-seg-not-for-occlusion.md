# ADR · 人脸分割不用于解决手遮脸溢出

> **结论**：当前分割权重解决不了「手遮脸时美白 / 磨皮叠到手上」。
> 手像素被判成皮肤，且皮肤概率比脸核心区还高；打开分割混合只会**加强**手部效果。
> **决策状态**：已接受 —— `BEAUTY_SEG_MIX` 保持默认 0，不把分割当作该痛点的解。
> 后续 A 方向（手部检测门控）**待决策、未接线**。
> **适用条件**：本仓库当前这两份权重（BiSeNet 19 类、selfie-multiclass 256×256 6 类）+ 合成素材。
> **失效说明**：若换用带「手部 / 遮挡类」或以被遮挡人脸微调过的模型，结论可能反转 —— 那是数据问题，不是管线问题。

## 上下文

2.16.2–2.17.3 的「手遮眼 → 美白遮罩叠到手上」修复链被用户实测判定整体无效，
2.16.1 做 R1 严格字面回档（见 [`../CHANGELOG.md`](../CHANGELOG.md) 2.16.1）。
随后把分割影子层 `BEAUTY_SEG` 当作替代方向评估，形成 2026-11-05 的实测结论稿。

## 决策

1. **不启用分割解决遮挡**。BiSeNet 19 类的类表里没有「手」，手背皮肤在色度上与脸颊几乎无差，
   模型只会逐像素答「这块皮像不像脸皮」。几何掩码失败的原因（手是肤色）没有被消除，
   只是换了个地方重犯。分割真正能排除的是头发、衣服、背景这些非肤色物体。
2. `BEAUTY_SEG_MIX` **保持默认 0**；不要因为「打开了分割」就以为痛点已解决。
3. 后续方向（**非当前实现**，仅登记待决策）：
   - **A 手部检测门控**（优先）：`hand.onnx` 每 3 帧跑一次，掌心框与人脸框求交，交叠超阈值即压低该区域增益；
     它是唯一在原理上有「手」这个类概念的判据。但成本虽已降下来，**仍需真实手遮脸素材才能定阈值**。
   - **B 方案 D 几何仲裁**：相对亮度指纹 + 四态机，零推理，作为 A 失效时的兜底；目前只到设计稿，
     见 [`../design/design-occlusion-mask.md`](../design/design-occlusion-mask.md)。
   - **C 收尾质量项**：P2 保边核调参、P4 非肤软衰减、P3 LUT 数据，痛点仍在只是不再恶化。

## 后果 / 证据

- 合成素材（同一帧真手贴回同一张脸，按 `beauty_skinseg.cpp` 逐行同口径跑 512 输入）：
  贴颊手区 `R=0.916 / g=0.869`，贴眼 `R=0.915 / g=0.894`；脸核心区仅 `0.558–0.589`；
  手区 `R>0.5` 占比 94.8% / 98.8%。
- 换 selfie-multiclass 256×256（有 `body_skin` / `face_skin` 两类）：贴颊手区
  `body_skin=0.589 / face_skin=0.158` 可分离，**但贴眼反转为 `face_skin=0.696`** —— 不能当结论用。
- 顺手重测推翻旧记录：手部检测 + 21 点此前记为「250–300 ms，太慢，否掉」，实测
  `hand.onnx` 6.5 ms + `hand_landmark.onnx` 1.8 ms（4 线程，Python ORT 1.31.1），约 8 ms/帧；
  插件自带 ORT 1.20.1 估计 12–16 ms。
- `hand.onnx` 分离度：整帧最高分 **0.924**（2 个 >0.5 锚点）、纯脸区 **0.041**（0 个）、纯灰图 0.012；
  对脸几乎零响应，正是分割模型做不到的。
- 推理成本：BiSeNet 512 NCHW 98.1 ms → selfie 256 NHWC **45.6 ms**；
  「只能 512」这条硬约束只属于 BiSeNet。
- **落地前还差一步**：`hand.onnx` 输出 `[745, 8]`，锚点布局不是 MediaPipe 标准那套，
  需反推锚点表；解锚点之前不要接进渲染链。

## 适用条件与失效说明

- 数值来自**合成素材**：手是同一帧胸前抠出后旋转贴回的，形态与「举手挡脸」不同，
  绝对值（0.92 等）**不可外推**；但分类归属「手 → 皮肤」由像素色度决定，不随姿态改变。
- 不能推断「所有分割方案都没用」，只对当前这份权重成立。
- 要下定论必须使用真实的手遮脸片段。
