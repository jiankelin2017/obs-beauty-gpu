## 默认值约定（很重要）

- **默认开**：不设 = 开，**只认 `=0` 关闭**（拼错环境变量会落在"开"这一侧，即已验证的安全侧）。
- **默认关**：不设 = 关，**只认 `=1` 开启**（拼错落在"关"这一侧，回到旧行为）。
- 数值型：不设 = 自动，设了按值生效。

|---|---|---|---|

## 二、生产链（默认开，改默认值就是这里）

| 开关 | 默认 | 作用 | 回退 / 说明 |
|---|---|---|---|
| `BEAUTY_GPU_SMOOTH_PROD` | **开** | Phase 3.5 GPU 磨皮生产路径（画面由 GPU 磨皮产出） | `=0` 退回 CPU 磨皮 |
| `BEAUTY_GPU_MASK` | **开** | GPU 掩码进生产链（替代 CPU 全帧掩码 + 上传） | `=0` 退回 CPU 掩码 |
| `BEAUTY_CHAIN_PROD` | **开** | 段区间钩子（磨皮→色调→五官→细节→美形留显存，5a） | `=0` 退回单段钩子 |
| `BEAUTY_CHAIN_OUT` | **开** | 链尾不回读（5b-1，直绘链纹理） | `=0` 退回回读+上传 |
| `BEAUTY_GPU_FRAME_RING` | **开** | 显存帧环（跳过对齐换帧的整帧上传，S2） | `=0` 关闭帧环 |
| `BEAUTY_DETECT_SMALL` | **开** | 检测输入走 GPU 预缩放 640×640 缩略图（S4b，需 `gpu_mask_chain` + 帧环） | `=0` 退回全帧回读（`tsm=0`） |
| `BEAUTY_ALLZERO_SKIP` | **开** | 全 0 参数直通短路（S1，跳过 GPU↔CPU 往返） | `=0` 关闭直通 |
| `BEAUTY_NOFACE_SKIP` | **开** | 无脸帧跳过整段处理（避免无掩码时全帧兜底磨皮） | `=0` 回到旧行为（全帧兜底） |
| `BEAUTY_AUTO_ROT` | **开**（3.2.0 新增） | **自动输入方向认定**：连续 `BEAUTY_AUTO_ROT_MISS` 次检测都无脸时，在**同一张输入图**上额外试 90°/270° 各一次推理，出脸即认定为有效方向（`effRot`）；此后按该方向重采样做检测、再把几何反变换回源坐标。解决「采集卡输出 1920×1080 横躺 + 场景项旋转成竖屏」这种接法下磨皮冻在横屏坐标、拉参数不响应、美白失效（面板「输入方向」2.15.2 已删，此前只剩 `BEAUTY_INPUT_ROT` 手工路）。命中后宿主自动改走全帧路径，每帧多一次全帧回读 | `=0` 逐字节回到 3.1.x 行为（离线确定性对拍须用它）。2026-11-06 真机验收：命中 270°、38 ms 后 `count=1`、滑块恢复响应 |
| `BEAUTY_AUTO_ROT_MISS` | `20`（≈1 秒 @30fps） | 自动方向探测的**触发阈值**：连续多少次「检不到脸」才启动试探。合法区间 3–600，越界忽略 | 调小 = 生效更快，但人刚走出画面时更容易白试；调大 = 更保守。真机实测从加滤镜到命中 **1.13 s** |
| `BEAUTY_AUTO_ROT_COOL` | `60`（≈3 秒） | 一次试探后的**冷却**（按检测次数算）。命中后不再试探（`effRot` 已非 0），这一条只对「试了也没人在画面里」的情形生效。合法区间 0–6000 | 调大 = 没人时更少烧推理；调小 = 人回来时更快重试 |
| `BEAUTY_ASYNC_DETECT` | **开** | 引擎异步人脸检测（离线对拍时须 `=0` 保证确定性） | `=0` 同步检测 |
| `BEAUTY_WARP` | **开** | 美形段（瘦脸/大眼/下巴）总闸：`=0` 时**整段不执行**，同时不再因美形参数去要掩码 | `=0` 逐字节回到 3.1.26 行为 |
| `BEAUTY_MASK_GEOM_ONLY` | 跟随内核（GPU 掩码链时为开） | 引擎只算几何、不画全帧 CPU 掩码（S4a） | `=0` 强制关闭 |
| `BEAUTY_MASK_SHAPE` | **3**（2.15.0 起；2.14.1 及以前是 0） | 掩码几何形状位掩码：`0` 矩形（3.1.19 行为）、`1` 脸椭圆、`2` 脖子椭圆、`3` 脸+脖子都椭圆、`+4` 脖子逐行跟肤色（**GPU 掩码链不支持 bit2**，置了就退回 CPU 掩码+上传）。**默认从 0 改成 3 的原因不是审美**：矩形边是直的，脸相对画面一歪（歪头、或源被转 90°）那条直边就横切在皮肤上，用户看到的就是「长方形美白遮罩」（`PROGRESS §9.47`） | `=0` 逐字节回到 2.14.1 的矩形掩码 |
| `BEAUTY_MASK_ROLL` | **开**（2.15.0 新增） | 掩码几何**跟随人脸滚转角**：θ 取两眼连线（YuNet `kps[0..3]`），几何绕脸心转 −θ，于是边界贴着脸自身的轮廓而不是画面轴。死角 2°（正立脸的关键点噪声 0.3~1.5° 不触发，保证黄金基准可对拍）。θ 里天然含 `input_rot` 的旋转，所以躺着的脸会得到 ±90° 的 tile，脸框宽高互换也被吸收。CPU 与 `mask.hlsl` 同一组式子 | `=0` 回到 2.14.1 的轴对齐几何 |
| `BEAUTY_MASK_EMA` | `90`（α = 90/256 ≈ 0.35） | **2.15.3**：掩码几何的一阶时间平滑（框中心 / 宽高 / 滚转角）。检测每跑一次框会抖 1~3 px、转角抖 1~3°，脸怼镜头或歪头时这点抖动就是「抽风闪」。合成噪声序列实测：边界中心抖动 std 0.67/0.75 → **0.38/0.43 px**，帧间 IoU 0.9852 → **0.9894**。大跳（中心位移 >8% 脸宽 / 宽高变化 >15%）直接采纳，不拖影。`0` = 关闭 | `=0` 逐字节回到 2.15.2 的掩码几何（黄金基准 maxdiff=0） |
| `BEAUTY_MASK_DUMP` | 不设（不落盘） | **2.15.6**：把**生产用的** GPU 皮肤掩码 1:1 落盘（`<目录>/gpu_skin_<n>_<w>x<h>.raw`，8-bit，值 0..255）+ 同名 `.txt` 一行几何（`shape/count/cx/cy/a/b/rc/rs/lw/lh/fe/...`）。最多 5 张、`frame_tag % 90 == 0` 触发（≈3 秒一张）。用来分辨「看得见的边界」到底是矩形 / 椭圆 / 皮肤轮廓 —— 只看日志数字分不出来。配套 `03_装机/9_run_obs_maskdump.bat` 一键启动 | 取消环境变量即关闭（默认关，零成本） |
| `BEAUTY_GPU_REGION` | **开**（2.14.0 起翻默认） | GPU 五官进生产链。2.8.1 起 4K 往返 **2.10 ms**（修复前 54–58 ms，根因是 geomOnly 帧拿不到 CPU 掩码导致五官链整段放弃，见 `PROGRESS §9.17`）。**判据已于 2026-11-04 补齐并按此翻默认**（T10-b，`PROGRESS §9.37`）：矩阵全 PASS，最坏 **1 灰阶**、最多 31 像素；翻默认后又补第 14 格**遮挡段**（`§9.40`，`maxdiff 0,1,0,1,0,0`，两遍逐位一致）与第 15–17 格**超小脸**（`§9.41`，掩码覆盖 1.4%/0.7%/0.4% 三档全 `maxdiff=0`），现共 **17 格 17/17 PASS**；多脸（`faceCount≠1`）两臂逐字节相同（设计内回退 CPU）。**侧脸 90° 判为输入域外**（`§9.41.3`：该姿态下 YuNet 先失效，到不了五官段）。**默认开、只认 `=0` 关闭** —— 不设 / `=1` / 拼错都落在开侧（`PROGRESS §9.39`）；启动日志打一行 `五官段（REGION）：GPU 生产链 / CPU 老路（原因）` | `=0` 退回 CPU 五官 |

## 三、opt-in（默认关，需显式开启）

| 开关 | 默认 | 作用 | 回退 / 说明 |
|---|---|---|---|
| `BEAUTY_INPUT_ROT` | 不设（= 0°，原样） | **3.2.0 起通常不再需要手工设**：方向由 `BEAUTY_AUTO_ROT` 自动认定。本开关保留给「要强制指定方向」的场合，语义未变：把输入当作已被旋转 0/90/180/270，检测在旋转后的整图上跑、几何再反变换回源坐标。只认 90/180/270 三个字面量，其余一律按 0。只对「摄像头物理侧装 / 采集卡输出横躺」这一种接法有意义；**选错会让检测整段失效**（YuNet 检不出 ±90° 的脸；2.15.0 起会退回 0° 并打一条 WARN） | 取消即回到 0°（交给自动认定）。面板项已删（用户 2026-11-04 反馈「没有一点效果」），能力保留给需要的人 |
| `BEAUTY_ASYNC_STAGE` | **关** | S3 暂存面双缓冲回读（输出整体晚一帧，≈33 ms，换掉 map 排队等待）。**与 S4b 缩略图路径互斥**：开启后 `tsm=0`，下载退回全帧 memcpy | 取消 / `=0`；须帧环可用 |
| `BEAUTY_MOTION_GPU` | **关** | 2.11.0 方案C：运动判定改在 GPU 上做 64×64 采样，640×640 缩略图**只在检测提交帧才回读**（不要的帧零回读）。**收益强烈依赖场景**：合成静止素材 720p 往返 **0.73→0.47（−36%）**、4K **2.22→1.85（−17%）**；真人出镜说话（`cam_real` 1080×1920）**同会话三臂**：关臂 **1.46–1.69**、`max` **1.57–1.65**（区间重叠 = **无显著收益**）、`rms` **0.72–0.86**、`rms`+still4 **0.93（−37%）** —— 差在判动率（3.4% vs 42.8%），根因是 S7 判据把「人说话时脸在动」当成「检测结果过期」（`PROGRESS §9.32`）。**生效域只有「单脸持续在场 + 上一帧全认领」**：无脸/多脸时缩略图路径本来就不开，与老版逐字节一致；该域内脸消失 1 帧无损失（`有脸 100% vs 98%`，`§9.31`） | `=0` / 不设 = 2.10.x 老节奏（逐字节不变）。**默认关**：真实场景要配合 `BEAUTY_DET_ADAPT_AGG=rms` 才有收益（单开它反而是 +6%~+13%，无收益）。推荐成套开 `MOTION_GPU=1 + AGG=rms + DET_ADAPT_STILL=4`（往返 −37%、超羽化 3.2%），依据见 `PROGRESS §9.34.6` |
| `BEAUTY_MOT_DUMP` | 不设 | **只诊断**：把喂给引擎的 64×64 运动小图存前 40 张裸 RGBA（16 KB/张）到指定目录。用来分清「判定一直在动」与「运动分支根本没进」——后者存到 0 张（`PROGRESS §9.31.3`） | 取消（不设即不开） |

## 回退原则（为什么这样设计）

1. 默认开的开关**只认 `0`**：拼错（如 `=ture`）不会误关，落在已验证的"开"侧。
2. 默认关的开关**只认 `1`**：拼错不会误开，落在旧的"关"侧。
   **例外（2.14.0 起）**：`BEAUTY_GPU_REGION` 已翻默认开，改按第 1 条只认 `0`，不再适用本条。
3. 每个新开关都要**实际跑一次 `=0`（或 `=1`）验证回退**——开关本身也是被验收对象（见 PROGRESS §9.9 跨阶段门禁）。

**两条硬约束（改之前先读）**：
1. **输入只能是 512**。这份"动态"模型只改了输入声明，图内部仍写死 512；用 1.20.1 喂
   256/288/320/384 会在 `Run` 里**整数除零、整进程崩溃**（0xC0000094，不是返回错误）。
   复核：`06_离线验证/segtest/ortprobe.exe model.onnx 512 256`。
2. **坐标有两套**。GPU 链开着时 worker 拿到的是宿主 640×640 缩略图，而人脸框是全帧

   表现为 `crop=1` 但 `uv=(0,0,1,1)`（等于没裁）。

此前"这份 BiSeNet 把手也判进皮肤类"的说法，是在整帧糊块输出上读 ch16（其实是**衣服**）
得出的，**已作废**；裁脸后手仍然会进皮肤类，但手在脸框外时被框边界挡住。
