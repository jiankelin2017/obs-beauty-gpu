# 修复：分割只在异步路径跑 + 无结果时 segMix 会把美颜乘成 0

> 日期：2026-11-05
> 影响面：`beauty_core.cpp`（分割调用位置）、`obs-beauty.cpp`（segMix 绑定）、`core_probe.cpp`（新增离线导出）
> 触发条件：① `BEAUTY_ASYNC_DETECT=0`；② `BEAUTY_SEG=1` 但模型没加载成功，或第一份结果还没回来
> 验证：离线回归 4 条基准逐字节相同（默认路径未受影响）；真实引擎链路首次跑通 selfie6 与 BiSeNet

## 一、分割只在异步路径跑，同步路径完全没跑

`skinsegRun()` 的调用点原先只有一处，在 `asyncWorker()` 里。也就是说：

| 配置 | 分割实际行为 |
|---|---|
| `BEAUTY_ASYNC_DETECT=1`（生产默认） | 正常，每 `BEAUTY_SEG_EVERY` 帧跑一次 |
| `BEAUTY_ASYNC_DETECT=0`（离线台、降级配置） | **一次都不跑**，`beautyCoreSegSeq()` 恒为 0 |

这条不是"少了个优化"，而是把两条路的行为拉开了：离线回归台（`core_probe`
强制同步检测）永远测不到分割，等于「分割链从上线起就没有桌面回归覆盖」。
之前 selfie6 的验证全靠 `06_离线验证/segtest` 那支**另写的**程序，它自己
复刻了一遍裁脸与坐标数学 —— 只能证明模型能用，证明不了插件里那条链对。

**改法**：把"该不该跑、跑哪一帧"抽成 `runSegIfDue()`，异步与同步两条路径都调它，
节流计数只有一个（`g_segTick`）。同步路径在 `buildMaskInto` 成功后立刻调用，
用的就是这一帧的 `faces_` 与同一套 `dsrc/dw/dh/gW/gH/mScale/mOx/mOy`。

## 二、没有分割结果时，`segMix > 0` 会把整张掩码乘成 0

`mask.hlsl` 的合成是：

```hlsl
float sk = pow(saturate(s4.r), segGamma);
float g  = sk * (1.0 - saturate(s4.b) * segNonSkinK);
v = (int)((float)v * lerp(1.0, g, segMix) + 0.5);
```

`segTex` 在第一份结果回来之前是 **1×1 白纹理**（`g_eWhite`），或者刚创建、
内容未定义的 512×512 动态纹理。白纹理下 `r=1, b=1`，而
`BEAUTY_SEG_NONSKIN` 默认已经是 **1.0**，于是：

```
g = 1 × (1 − 1×1) = 0   →   lerp(1, 0, segMix) = 0   →   掩码全 0
```

结果不是"分割没生效"，而是**美白/磨皮/清晰/五官/美形全部消失**，画面上只剩
原相机。更要命的是"模型路径写错 / ORT 没起来"也走同一个下场：`beauty_e_ensure`
只留一条 WARNING，用户看到的是"开了 BEAUTY_SEG=1，美颜没了"。

**改法**（一行，宿主侧）：绑定 `segMix` 时按有没有第一份结果门控 ——

```cpp
gs_effect_set_float(p, g_segSeq ? g_segMix : 0.0f);
```

`g_segSeq` 只在 `beauty_e_update()` 真正上传过纹理后才非 0，所以：
模型没起来 / 首帧未到 → `segMix` 生效值为 0 → 逐字节退回纯几何路径（与改动前一致）；
有结果之后才按 `BEAUTY_SEG_MIX` 走。这条同时把"头几百毫秒美颜闪烁"一并消掉。

## 三、顺带：分割终于能在桌面上跑完整链路

给 `core_probe.dll`（只进离线 DLL）加了两个导出：

- `BeautyCoreSegDump(path)` —— 落盘 16 字节头（`w,h,cropped,ms`）+ 16 字节
  `uv[4]` + 512×512×4 RGBA。
- `BeautyCoreSegInit()` —— 分割是否真的启动（模型是否加载成功）。

配套脚本 `06_离线验证/seg_engine_probe.py`。它设好 `BEAUTY_SEG*` 环境变量后调
`BeautyCoreMask`（内部强制同步 → 走的就是修好后的 `runSegIfDue`），再 dump 语义纹理，
打印 `crop/uv/ms` 与脸区、裁切框、整帧的 R / B / R×(1−B) 均值，并输出四联图。

## 四、验证结果（`goldens/frame_1280x720.raw`，真人单脸）

两个档位跑同一条引擎链路，**`uv` 完全一致** —— 说明裁脸/坐标映射与模型无关：

| 档位 | crop | uv | 推理 ms | 脸中心 R | 脸中心 B | 脸中心 R×(1−B) |
|---|---|---|---|---|---|---|
| selfie6（256） | 1 | (0.3313, 0.0625, 0.3672, 0.6528) | 47~54 | 0.997 | 0.070 | **0.930** |
| bisenet19（512） | 1 | 同上 | 88 | 0.836 | 0.019 | 0.819 |

- 整帧 `R×(1−B)` 只有 0.05：脸以外的头发/背景/衣服基本被压掉（`B` 整帧 0.17）。
- selfie6 在真人帧上的语义正确：皮肤贴着脸部轮廓，头发与背景都在非肤通道里
  （证据图 `_seg_selfie6.png` / `_seg_bisenet.png`，四联：裁切 | R | B | 提亮区）。
- 默认路径（`BEAUTY_SEG=0`）离线回归 4 条基准 **maxdiff=0，逐字节相同**。

## 五、没改的东西

- `segtest` 那支独立程序保留，它验的是模型本身（类别顺序、输入口径），与引擎链路
  不重复；新的 `seg_engine_probe.py` 验的是"插件里那条链"。
- 分割仍只在 `BEAUTY_SEG=1` 时创建 ORT 会话，默认零开销。
