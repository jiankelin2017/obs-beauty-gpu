# 修复：GPU 链上「纯锐化」整段失效（磨皮=0 时掩码为空）

日期：2026-11-05
版本：2.16.1 → 3.1.65（core）
涉及文件：`01_源码/beauty_core.cpp`、`01_源码/obs-beauty.cpp`

---

## 1. 用户报的现象

「锐化，去斑痘无效果。下巴 效果需要优化。」

其中祛斑与下巴是强度/方向问题（已在前一轮处理），**锐化是一个真实的功能性 BUG**：
在 OBS 里把「锐化」拉满，画面**一个像素都不变**。

## 2. 怎么测出来的

GUI 自动化在本机被安全策略拦（Start-Process / COM / Add-Type 全部拒绝），
改为走 OBS 内置的 **obs-websocket**（4455，`auth_required=false`）：

- `06_离线验证/ws_probe.py` —— 列场景/源/滤镜、抓帧、改参数
- `06_离线验证/ws_three.py` —— 用一张**静态人脸图**当源，把每一项单独拉满，
  各截一张 `GetSourceScreenshot`，再做逐像素差分

选静态图而不是摄像头，原因有两个：当时摄像头对着天花板（画面里没人脸），
而且静态图与 `06_离线验证/goldens/frame_1280x720.raw` 是同一张脸，可以
**直接和 CPU 离线台对拍**。

> 一个环境坑：本机 `HTTP_PROXY=127.0.0.1:4433`，websocket-client 会把
> 127.0.0.1 的连接也塞进代理隧道，报 502。脚本里必须显式清掉代理并给
> `http_no_proxy=["127.0.0.1"]`。

## 3. 关键观测（修复前，真实 GPU 链，面板 100）

| 开的项 | 变化像素 | max | 判定 |
|---|---|---|---|
| 只开「锐化」 | **0** | 0 | 与关滤镜**逐字节相同**（png md5 一致） |
| 只开「全局锐化」 | 390 416 (42.4%) | 76 | 有效，全帧 |
| 锐化 + 全局锐化 | 390 416 | 76 | 与"只开全局"完全相同 → 脸内那档贡献 0 |

再用磨皮做对照：

| 组合 | 变化像素 | max |
|---|---|---|
| 磨皮 100 | 60 075 | 13 |
| 磨皮 100 + 锐化 100 | 61 359（叠加 52 777） | 63 |

**结论：磨皮>0 时脸内锐化有效；磨皮=0 的「纯锐化」整段失效。**
这正好是用户的使用场景（他只拉锐化，不拉磨皮）。

## 4. 根因

`beauty_core.cpp:1672`（旧）：

```cpp
forceCpuMask_ = ((t <= 0.0f) && (wantTone || wantClarity));
```

这是 2.16.1 修「美白完全没效果」时加的补丁，但**条件里漏了 `wantFaceDetail`**。
于是下面这条链成立：

1. 磨皮=0 → 段区间钩子不被调用（它只在 `t > 0` 时跑）→ GPU 掩码链一帧都不跑，
   没有任何东西替 CPU 画掩码；
2. 可 `geomOnly` 仍然成立（`!forceCpuMask_ && mapped && 单脸 …`）→ CPU 也一个
   像素都不画；
3. `skin` 纹理整张是空的 → `detail.hlsl` 里 `m = 0` → `fwF = m · dFine` 恒为 0，
   **脸内锐化/中频回填整段失效**，只剩 `fwG = (1−0)·dGFine` 的全局项。

宿主日志同时给了正面的印证：

```
self-check: out_tex mean=55.5 | detail in=3.077 out=3.077 (+0.0%) | ... faces=0
```

`detail in == out` 就是"细节段什么都没改"。

### 顺带修的第二处

`obs-beauty.cpp` 里 detail 段的 `no_mask` 判据原来写的是 `job.mask == NULL`。
但 GPU 掩码链接管时走的是 geomOnly 帧，引擎**故意不画 CPU 掩码**，
`job.mask` 必为 NULL，而掩码实际由宿主按几何重画在 `mask_skin_use`（GS_RGBA，
值写在 `.r`）上 —— 那是一个可用的掩码。旧判据把这类帧也当成"没有掩码"。

改成与宿主 `gpu_mask_ok` 同构的判据（见该处注释：「有掩码可用」= `job.mask || geomOnly`）：

```cpp
const bool no_mask_for_detail =
    (job.mask == NULL) && (job.maskGeomOnly == 0);
```

## 5. 修复

```cpp
// beauty_core.cpp
forceCpuMask_ = ((t <= 0.0f) &&
                 (wantTone || wantClarity || wantFaceDetail));
```

磨皮=0 且要面部锐化时，强制引擎画全帧 CPU 掩码。

> 下巴 `22552 px` 在 GPU 与 CPU 两边是同一个数字，逐字节相同 —— 3.1.64 的

### 6.3 黄金基准

`python offline_regress.py check` → 4 条基准 **maxdiff=0，全部通过**。
CPU 引擎路径未受影响（`mapped=false` 时 `geomOnly` 本来就不成立）。

## 7. 仍然存在的限制

锐化修好后数值上确实生效（4.01% 像素、max 16），但**视觉上仍旧偏弱**，
把图放大 2 倍并排也几乎看不出差别。原因不在代码：

- 该帧脸区 `|hf|` 中位数只有 **0.43 灰阶**、P90 1.56 —— 增益 1.0 时大量像素
  落在 ±0.5 以内被取整吃掉；
- 素材本身偏糊（摄像头成像），高频信息本来就少。

想更扎眼只能提高 `BEAUTY_FACE_SHARP_GAIN`（现 1.0）到 1.5~2.0，
代价是噪点同倍放大（这台摄像头的皮肤噪声与 `|hf|` 同阶）。
