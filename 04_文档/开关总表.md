## 默认值约定（很重要）

- **默认开**：不设 = 开，**只认 `=0` 关闭**（拼错环境变量会落在"开"这一侧，即已验证的安全侧）。
- **默认关**：不设 = 关，**只认 `=1` 开启**（拼错落在"关"这一侧，回到旧行为）。
- 数值型：不设 = 自动，设了按值生效。

## 三、opt-in（默认关，需显式开启）

| 开关 | 默认 | 作用 | 回退 / 说明 |
|---|---|---|---|
| `BEAUTY_ASYNC_STAGE` | **关** | S3 暂存面双缓冲回读（输出整体晚一帧，≈33 ms，换掉 map 排队等待）。**与 S4b 缩略图路径互斥**：开启后 `tsm=0`，下载退回全帧 memcpy | 取消 / `=0`；须帧环可用 |
| `BEAUTY_GPU_REGION` | **关** | GPU 五官进生产链。2.8.1 起 4K 往返 **2.10 ms**（修复前 54–58 ms / 17.7–18.4 fps，根因是 geomOnly 帧拿不到 CPU 掩码导致五官链整段放弃，见 `PROGRESS §9.17`）。**仍 opt-in 的理由是「缺可靠判据」**：截图对拍在 geomOnly 路径不成立（四路子项差异完全相同，§9.19），同帧自检在 **5 个样本 × 2 个分辨率**上 `maxdiff≤1`（§9.20.2，非逐字节等价） | `=0` 退回 CPU 五官 |
| `BEAUTY_MOTION_GPU` | **关** | 2.11.0 方案C：运动判定改在 GPU 上做 64×64 采样，640×640 缩略图**只在检测提交帧才回读**（不要的帧零回读）。同会话配对 720p 往返 **0.73→0.47 ms（−36%）**、4K **2.22→1.85 ms（−17%）**；六配置 `maxdiff=0`；运动素材对齐 180/180 但 +0.05 ms（`PROGRESS §9.29`）。**生效域只有「单脸持续在场 + 上一帧全认领」**：无脸/多脸时缩略图路径本来就不开，与老版逐字节一致；该域内脸消失 1 帧无损失（`有脸 100% vs 98%`，`PROGRESS §9.31`） | `=0` / 不设 = 2.10.x 老节奏（逐字节不变）。**默认关**：只剩「真实摄像头噪声下闸门是否仍安静」一条未验，与 P0-11 阶段 2 同批翻默认 |
| `BEAUTY_MOT_DUMP` | 不设 | **只诊断**：把喂给引擎的 64×64 运动小图存前 40 张裸 RGBA（16 KB/张）到指定目录。用来分清「判定一直在动」与「运动分支根本没进」——后者存到 0 张（`PROGRESS §9.31.3`） | 取消（不设即不开） |

## 设置方法

- **当前会话（临时）**：`set BEAUTY_XXX=1`（cmd）或 `$env:BEAUTY_XXX="1"`（PowerShell）。
- **持久（用户级，双击 OBS 也生效）**：`setx BEAUTY_XXX 1`；撤销 `setx BEAUTY_XXX ""`。
- **只对某次启动**：用 `03_装机/6_launch_obs_test.bat` 等启动器注入，或 `verify_s1_correct.py --env K=V`。

## 回退原则（为什么这样设计）

1. 默认开的开关**只认 `0`**：拼错（如 `=ture`）不会误关，落在已验证的"开"侧。
2. 默认关的开关**只认 `1`**：拼错不会误开，落在旧的"关"侧。
3. 每个新开关都要**实际跑一次 `=0`（或 `=1`）验证回退**——开关本身也是被验收对象（见 PROGRESS §9.9 跨阶段门禁）。
