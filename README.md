# OBS 美颜 GPU 版

> **一句话**：把一个原本全在 CPU 上的五段人脸美颜，整体搬到 GPU 的 OBS 滤镜。
> 生产默认路径 **4K 往返 ≈2.3–2.8 ms**、**720p ≈0.8–1.5 ms**（移植前 4K 是 81 ms / 约 7 fps）。
>
> - **装机 + 已验收：2.10.0**（`MD5 C040187A05D55BFEEC18753CF118DD6A`，572,928 B）
> - **开发中：2.10.1**（= 2.10.0 + 一条输入旋转告警，**已编译、未装机、未验收**，`MD5 0BC8358428B43627D765AE3B0C05AF76`）
> - 引擎：`gpu/2.0.0`（GPU 路径）｜ `core/1.6.0`（CPU 兜底 + 离线 golden 基准）
> - 本文按 **2026-11-04 的源码**逐条核对；每个数字都指明出处（`PROGRESS §x`），不写推算值。

---

## 1. 它是什么

一个 OBS 视频滤镜（`obs_beauty_filter`），挂在任意源上，输入源纹理、输出**同尺寸**纹理：

```
源纹理 ──► 磨皮 ──► 色调(清晰/美白/红润) ──► 五官(立体/亮眼/黑眼圈/法令纹/祛斑)
        ──► 细节(锐化/全局锐化) ──► 美形(瘦脸/大眼/下巴) ──► 输出
                    ▲
        人脸检测（YuNet onnx + YCbCr 肤色椭圆）──> 掩码 / 保护椭圆 / 五官几何
```

设计边界（有意为之，不是缺陷）：

- **不改输出几何**：滤镜输出恒为源尺寸、朝向不变；竖屏/旋转由 OBS 场景项负责（`§9.21`）。
- **不碰父源**：无 `obs_source_set_width/height`、无增删滤镜，滤镜链只读源纹理。
- **默认参数不为零**：磨皮出厂 **20**（其余 13 项为 0），所以「装上就有轻微磨皮」是设计。

## 2. 正向：确认可用的东西

### 2.1 性能（生产默认，单脸，RTX 5060 Laptop）

| 场景 | 实测 | 对照 | 出处 |
|---|---|---|---|
| 4K 往返 | **≈2.3–2.8 ms**（长跑中位 2.28，1.99–2.96） | 移植前 81 ms（≈7 fps） | §9.5.4 |
| 720p 往返 | **≈0.8–1.5 ms** | 移植前 15.71 ms | §9.3.2 / §9.12.1 |
| 全 0 参数直通 | **0.00 ms**（整段跳过，等价滤镜禁用） | — | §9.2 |
| 4K 检测输入（S4b） | 往返 9.5–9.8 → **2.45–2.58（−74%）** | 原先把整帧 33 MB 回读 | §9.5.3 |
| 显存帧环（S2/S2b） | 720p **2.17→1.29（−41%）**、4K **11.39→8.28（−27%）**；再按需拷贝 720p **2.00→1.50（−25%）** | — | §9.3.1 / §9.3.2 |
| 静止 CPU（S7） | 0.476 → **0.101 核（−79%）** | 每帧提交检测 | §9.13 |
| 五官段 GPU 化（opt-in） | 4K **49.34→8.88（5.6×）**、720p **11.47→1.58（7.3×）** | 全 CPU | §9.17 |

### 2.2 正确性（逐像素判据，不是「看着差不多」）

| 结论 | 判据 | 出处 |
|---|---|---|
| 五段各自与 CPU 逐像素等价 | `maxdiff ≤1`（多数 0） | §三 里程碑 |
| 六个配置整体等价 | `2.9.1 vs 2.10.0` **maxdiff 全 0、变化像素 0** | §9.28.2 |
| 五官段 GPU/CPU 同掩码 | 720p/4K 各 5 样本 **maxdiff ≤1** | §9.20 |
| 祛斑真的改画面 | 0 档 **0 像素**、40/100 单调（720p 48,926 px / 4K 220,005 px） | §9.23 |
| 祛斑帧间稳定 | 连续 60 帧 `diffpx` **极值比 1.00**（判据 ≤1.2） | §9.24 |
| 默认路径零影响 | 直通 vs 滤镜禁用 `maxdiff=0` | §9.2 |

### 2.3 稳定性

| 场景 | 结果 | 出处 |
|---|---|---|
| 4K 30 min（S2 默认路径） | **54,180 帧**零 D3D11/驱动异常，往返 8.74 ms | §9.3.1 |
| 4K 30 min（S3 opt-in） | 301 窗零异常（性能不划算，见负向） | §9.16 |
| 4K 20 min ×2（S4b1 最终版） | `tskip>0` **0/201 窗**，30.1 fps，`gate.py` PASS | §9.5.4 |
| 切换/热重载/冷启动 | 画布 720p↔1080p↔4K 来回 9 次不崩、热重载 3 轮、冷启动 7 次 | §9.3.1 |

### 2.4 工程与部署

- **装机脚本** `03_装机/7_install_gpu.ps1`：备份 → 装 dll + `data/shaders/*.hlsl` → 逐文件 MD5 校验 → 不一致即 `throw`；**拒绝在 OBS 运行时装机**。
- **shader 单一来源**：只有 `01_源码/shaders` 是手写源，其余（打包产物、装机运行时、开发 junction）全部由脚本生成（P2-3）。
- **安装包** `07_安装包/build_setup.ps1`：一条命令从 `02_构建` + `01_源码/shaders` 重打 `Setup.exe`，拷贝前先清空目标目录（防幽灵文件）。
- **一键回退**：每个新特性都有 `BEAUTY_*` 开关（见 `04_文档/开关总表.md`），默认值只认「`0` 关 / `1` 开」以防拼错。
- **采集前置 GPU 闸** `05_验证/gpu_guard.py`：显存 >3500 MiB 或重度占用时拒绝起 OBS，避免测出虚高帧时再误判成源码问题（§9.14）。

## 3. 负向：已知限制、缺陷与风险

### 3.1 产品级（用户能感知）

| # | 现象 | 触发条件 | 影响 | 现状 / 回退 |
|---|---|---|---|---|
| N1 | **输入方向（`input_rot`）不生效且无提示** | 走全帧检测的帧（多脸 / `DETECT_SMALL=0` / `ASYNC_STAGE=1` / 镜像 / 上一帧未被链全认领）；**或开了任一五官参数**（`GPU_REGION` 默认关 → REGION 落 CPU → 非全段认领） | 竖屏摄像头用户以为设了旋转就对齐，实际掩码/五官全在错位置 | 2.10.1 起打**一次性 WARN** 说明原因；真修见 P0-11 阶段 2（`§9.28`） |
| N2 | **五官段（4K 5.6×）默认拿不到** | `BEAUTY_GPU_REGION` 是 opt-in | 开五官参数时整帧回到 CPU 路径（4K 从 2.3 ms 涨到数十 ms） | 维持 opt-in：像素样本只有 5/档、缺 4K 长跑、未做翻默认决策（§9.26.4） |
| N3 | **多脸场景收益归零** | 画面里 ≥2 张脸 | 缩略图检测与显存帧环都要求单脸 → 全部绕开，退回全帧回读；`input_rot` 同时失效 | 设计边界；素材统计多脸只占 1.59%，不立项（§9.18.2） |
| N4 | 开箱即改画面 | 磨皮默认 **20** | 「默认零影响」只对参数全 0 成立，不是装上不变 | 有意为之；要零影响把磨皮拖到 0 |
| N5 | 竖屏/横竖混用时观感像「被拉伸」 | 画布 1080×1920 + 源 1280×720 + 场景项框 = 画布尺寸 | 与滤镜无关，是场景项几何；历史上被误判成滤镜 bug 查了三轮 | 见 §三「BUG 3 更正」；滤镜侧无解 |

### 3.2 性能 / 质量上的已知妥协

| # | 事实 | 说明 |
|---|---|---|
| N6 | **S3 暂存面双缓冲（opt-in，永不转默认）** | 720p −43%、4K −22%，但在 2.8.0 默认组合下 4K 反而 **+1.53 ms**，且输出晚一帧；与 S4b 互斥（§9.16） |
| N7 | **4K 帧环的 M1 有 24 px 的 1 灰阶差（0.0003%）** | 所以 4K 帧环路径只能说「≤1 灰阶、0.0003% 像素」，**不能说逐字节等价**（§9.5 尾注） |
| N8 | **`tskip` 偶发**（负载相关） | 机器有其他负载时约 1 帧/窗被判同槽挤掉；接受（加第 4 槽要 33 MB/帧）（§9.5.4） |
| N9 | **S5 通道打包：否决** | 斜率实测 1.2 µs/draw（720p）/10 µs（4K），draw 23→15 只省 0.08 ms，差门槛一个数量级（§9.12.2） |
| N10 | **S6 去两趟 Copy：降级** | 只省 0.02 ms，只剩「顺手清理接口」的价值（表 C） |
| N11 | **「2b 缩小检测输入」未决** | 能再降 ~1.9 ms，但不再是逐字节等价，需要产品拍板（表 C） |

### 3.3 工程 / 流程级（接手的人会踩）

| # | 事实 | 后果 |
|---|---|---|
| N12 | **二进制不入库**：`02_构建/*.dll`、`07_安装包/{Setup.exe,*.dll,*.obj,*.res,shaders}` 全在 `.gitignore` | 仓库里只有源码与文档；「当前装机是哪一版」只能靠 MD5 与日志确认 |
| N13 | **安装包会与构建产物脱节** | 实例：2.9.1 装好一个月，`Setup.exe` 还停在 2.9.0（带旧 `region.hlsl`）。发布前必须手动跑 `build_setup.ps1` |
| N14 | **工具不校验「dll 版本 == 源码 `BEAUTY_BUILD_STR`」** | 装错版本不会报错，只能看日志 `init OK (v2.10.0 …)`（表 B 第 11 条缺口） |
| N15 | **UI 是独立 dll**（`obs-beauty-ui`，日志里的 `v3.1.39`） | 版本轴与滤镜不同步，改 UI 要另建一份 dll；面板文案改动不随滤镜版本走 |
| N16 | **CPU 分支（1.0.0）与 UI 源码不在本仓库部署** | 本仓库只出 GPU 滤镜 dll；CPU 版仅用于 golden 基准对照 |

### 3.4 验证工具本身的坑（每条都真实踩过）

| # | 坑 | 正确做法 |
|---|---|---|
| N17 | `--collection X` 匹配的是集合 JSON 里的 `name` 字段，**不是文件名**；打偏是**静默**的 | 唯一判据：插件日志 `target=` 尺寸 == 素材尺寸（§9.23.3） |
| N18 | 面板单位是 **0..100**，不是 0..1 | `thin_face: 0.6` 等于拖到 0.6%（§9.19 整轮对拍因此跑在 1% 强度） |
| N19 | 参数要在**起 OBS 之前**写进集合 | 自检取「第一个满足条件的帧」，等 WebSocket 连上再下发已经晚了 |
| N20 | OBS **退出时会改写集合**（`pos_rel`/`pos` 被重算） | 两版对比前先恢复同一份集合快照，否则同图也能差 99.994%（§9.28.2） |
| N21 | 收益只认**同会话配对 A/B** | 搬运项跨会话不可比；4K 引擎容差另定 25%（§9.1.2） |
| N22 | 长跑日志会被轮转（OBS 只留最近 10 份） | 跑完立刻拷到 `05_验证/out/logs/` |
| N23 | 合成人像常因**色度过低落在肤色椭圆外** → `faces=0`、掩码 0% | 用 `make_front_assets.py` 的色度校正，别看 cv2 的检测结果（§素材） |

### 4.2 三条命令

```bat
:: 编译（需要 VS + obs-studio-32.1.1 源码树 + onnxruntime 头；脚本按内容探测路径）
powershell -ExecutionPolicy Bypass -File 02_构建\build_gpu.ps1

:: 装机（OBS 必须关闭；dll + 6 个 hlsl，备份 + MD5 逐文件校验）
powershell -ExecutionPolicy Bypass -File 03_装机\7_install_gpu.ps1

:: 重打安装包（从 02_构建 + 01_源码\shaders）
powershell -ExecutionPolicy Bypass -File 07_安装包\build_setup.ps1
```

装机后看日志三行就能判健康：`init OK (vX.Y.Z, engine=gpu/2.0.0, region=…)`、
六个 `xxx.hlsl 已加载`、`引擎资源已预热 WxH`。

## 5. 验证怎么做

三条线，各管一段，缺一条就会得出错误结论：

| 线 | 命令 | 管什么 |
|---|---|---|
| 离线 | `05_验证/verify_{tone,smooth,region,detail,warp,mask}_compiles.py` | 着色器编译 + 入口签名 |
| 离线（引擎） | `06_离线验证/offline_regress.py check` | CPU 引擎 golden 四例（**动引擎接口/S4/S7 必跑**） |
| 装机采集 | `05_验证/verify_s1_correct.py capture/compare`、`verify_region_samemask.py`、`verify_spot_pixels.py` | 六配置逐像素、五官同掩码、祛斑像素量 |
| 性能 | `s0_lock.py` → `gate.py --skip-transfer --cmp`；收益用 `ab_pair.py` | 基线复绑 / 门禁 / 配对收益 |
| 稳定性 | `soak_s2.py soak --minutes 30` | 长跑、切换、热重载 |

判据口径（2026-11 定稿）：**搬运项跨会话不可比**（只由配对 A/B 判），跨会话只判引擎项 + 健康项
（`gskip/tskip` 取最坏窗口）。完整工具说明与 18 条坑：[`05_验证/README.md`](05_验证/README.md)。
