# OBS 美颜 GPU 版（方案 A：GPU 主 + CPU 辅/兜底）

> 从 `D:\插件\OBS美颜源码`（滤镜 v3.1.39 / 引擎 core 1.4.0）移植的 **GPU 化分支**。
> 详细方案见 [`04_文档/方案A_GPU移植开发计划.md`](04_文档/方案A_GPU移植开发计划.md)，
> 进度追踪见 [`PROGRESS.md`](PROGRESS.md)，文档索引见 [`04_文档/README.md`](04_文档/README.md)。

## 为什么做这个版本

**动机：降 CPU 功耗。** CPU 版每帧要把整帧从 GPU 下载到 CPU（~8 MB @1080p RGBA）、跑纯 CPU
像素引擎、再上传回 GPU。这笔往返既占 CPU 算力又增加每帧延迟。GPU 版让画面全程留显存，
用 D3D11 着色器直接算，消除往返。

## 当前架构

- **磨皮 → 色调 → 五官 → 细节 → 美形 五段全部在 GPU 上串联**：由引擎内回调
  `beautyCoreSetSmoothHook` / `beautyCoreSetChainHook` 在 `process()` 磨皮段被问一次，
  返回认领的段位掩码，五段全程留显存，**只在链尾回读一次**；引擎强校验「认领必须是
  `SMOOTH→TONE→REGION→DETAIL→WARP` 前缀」，非前缀整份丢弃退回 CPU。
- **为什么钩子必须挂在引擎内**：掩码↔帧对齐会在 `process()` 内部把 `src` 换成上一帧的
  `heldFrame_`（实测 71% 的帧如此），外侧接管必然错帧。钩子拿到的才是本帧真正要处理的
  那份帧和当帧生效的 mask/protect。
- **人脸检测不动**：原本就走 ONNX Runtime 的 DirectML EP（已 GPU）。
- **CPU 常态只做轻活**：landmarks→位移图/掩码的小预处理、常量缓冲、OBS 胶水。
- **CPU 引擎保留作兜底 + golden 基准**：`BEAUTY_GPU=0` 一键回退；每个 GPU 算子都用 CPU
  输出做逐像素对拍。钩子任何一步失败都逐帧回退 CPU，**结果与不挂钩子时逐字节相同**。

>
> **版本号递增规则（GPU/CPU/UI 三套共用，2026-11-02 重置）**：小更新 → 最右 +1（x.x.N）；重要更新 → 中间 +1、最右归零（x.N.0）；超大型更新（架构/不兼容） → 最左 +1、后两位归零（N.0.0）。

### 4K 线性度结论（决定后续路线）

### 当前边界（能力范围，不是待办）

1. **单脸**：GPU 掩码与 GPU 五官都只做单脸；2 脸及以上整帧回退 CPU（画面正确，只是慢）。
   美形最多 8 脸、磨皮/细节走并集掩码，多脸也能正确工作。
2. **检测仍在 CPU**：人脸检测（YuNet）+ 掩码构建留在 CPU，4K 下 `下载 4.7 + 掩码 2.5 ≈ 7.2 ms`。
   这一段不属于「算子移植」，要动需另立项目（缩小检测输入 = 2b，或检测搬 GPU）。
3. **4K 帧环路径是「≤1 灰阶」而非完全逐字节**：走显存帧环时 R1 实测 24 px 的 1 灰阶差（0.0003%）。
   其余四段在 720p/4K 均为 `maxdiff ≤ 1`。
4. **跨会话数字不可横比**：不同次启动的机器背景负载会漂（实测同一构建 3.39→3.76 ms），
   定量结论一律用**同会话 A/B**。

## 与上游的关系

本目录是 `OBS美颜源码` 的**独立移植分支**，不是原地修改。上游的 CPU 引擎、标定
（`lvI/lvE/lvT`）、79.0 分对齐成果是整个 GPU 化的 golden 基准，移植过程必须保持量化对齐不降。
